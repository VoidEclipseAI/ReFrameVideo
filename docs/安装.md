# ComfyUI 安装与部署指南

范围：ReFrameVideo 浏览器前端 + Python 后端 + ComfyUI 推理，包含分割、参考图编辑和视频生成，以及可选的云端图片 / 视频 API。训练环境不在本指南范围内。

## 1. 先了解三个组件

```text
浏览器 → ReFrameVideo 后端（默认 8765，同时伺服 web/ 前端）→ ComfyUI（通常 8188）
```

前端提供画布和编辑操作；后端处理项目、视频、蒙版和工作流；ComfyUI 加载模型并推理。模型放在运行 ComfyUI 的电脑上，原始视频路径则必须能被运行后端的电脑访问。两台电脑可以不同。

本仓库包含前端（`web/`）、后端（`app/`）和自研 ComfyUI 节点（`comfyui/ComfyUI-Reframe/`）。项目 LoRA 在 [Hugging Face](https://huggingface.co/VoidEclipseAI/ReFrameVideo-LoRA) 和 [ModelScope](https://modelscope.cn/models/VoidEclipseAI/ReFrameVideo-LoRA)（国内下载更快）。

## 2. 环境与目录

实际测试过的环境：

| 组件 | 测过的版本 / 配置 |
|---|---|
| ReFrameVideo 后端 | Windows 10，Python 3.10 和 3.13 |
| ComfyUI | 0.39.0 和 0.45.5（SAM、H3 视频、Qwen Image 2.1 都跑通）；MiniMax H3 Image 改图和 H3 Image PE 需要 0.45.0 以上（0.45.5 只确认过能识别相关节点，改图没有完整跑通） |
| 显卡 | ComfyUI 跑在另一台 RTX 4090（24 GB）上，后端所在的电脑不需要显卡 |
| Linux / macOS | 代码按跨平台写，没有实际跑过 |

目前没有系统测量最低显存、内存、磁盘容量，不把 4090 写成硬性最低要求。H3 主模型及文本编码器较大，磁盘还需要容纳视频、预览、蒙版和生成中间文件。先用短片验证环境。

仓库结构：

```text
ReFrameVideo/
├─ start.py / start.bat       一键启动（后端 + 前端一个端口）
├─ requirements.txt           后端 Python 依赖
├─ LICENSE                    许可证（AGPL-3.0）
├─ README.md / README_zh.md   项目说明（英文 / 中文）
├─ app/                       Python 后端（含 prompts/、prompt_format.py）
├─ web/                       浏览器前端（不需要构建）
├─ comfyui/ComfyUI-Reframe/   要装进 ComfyUI 的自研节点
├─ workflows/                 H3 示例工作流（API 格式）；image/、video/ 放自定义工作流（见各自 README）
├─ docs/                      说明文档
├─ app_settings.json          运行时生成的设置（不进 git）
└─ projects/                  项目数据（默认位置，不进 git）
```

不要只复制 `server.py`；它依赖 `app/` 里的其他模块和提示词文件，前端在 `web/`。

## 3. 安装 ComfyUI

Windows 可按 [ComfyUI 官方便携版指南](https://docs.comfy.org/installation/comfyui_portable_windows)下载与显卡匹配的包，解压后运行 `run_nvidia_gpu.bat`。以下将包含 `main.py`、`models/` 和 `custom_nodes/` 的目录称为 `ComfyUI/`（便携包里是 `ComfyUI_windows_portable\ComfyUI\`）。

先确认浏览器能打开 ComfyUI，再安装模型和节点。单机使用 `http://127.0.0.1:8188`。跨电脑时按官方指南设置监听地址和防火墙，只允许可信网络访问；ReFrameVideo 的 `--comfy` 填运行 ComfyUI 的电脑地址。

ComfyUI 自带自己的 Python 环境，后文 ReFrameVideo 后端的虚拟环境是另一套环境。插件依赖应安装到 ComfyUI 的 Python 中。

模型来源：

- H3：[Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main)，按仓库中的 `diffusion_models`、`text_encoders`、`vae` 分类下载对应文件。
- H3 Image：[Comfy-Org/MiniMax-H3-Image](https://huggingface.co/Comfy-Org/MiniMax-H3-Image/tree/main)（模型、VAE），PE 在 [Comfy-Org/Qwen3.5](https://huggingface.co/Comfy-Org/Qwen3.5/tree/main/text_encoders)。要 ComfyUI 0.45.0 以上。使用前请阅读许可原文（见 [MiniMax-H3-Image 模型仓库](https://huggingface.co/Comfy-Org/MiniMax-H3-Image/tree/main)）。
- SAM：[Comfy-Org/sam3.1 的 checkpoint](https://huggingface.co/Comfy-Org/sam3.1/tree/main/checkpoints)。
- Qwen：从 [ComfyUI 官方 Qwen Image 2.1 教程](https://github.com/Comfy-Org/docs/blob/main/tutorials/image/qwen/qwen-image-2-1.mdx)进入模型下载链接，核对上表文件名。不要误下旧版 Qwen Image Edit；当前代码使用 2.1 专属节点。未逐个验证所有 Qwen 文件的下载可用性。
- MatAnyone2：按 [ComfyUI-MatAnyone 作者说明](https://github.com/FuouM/ComfyUI-MatAnyone)中的模型下载入口获取，放进插件的 `checkpoint/`。
- 项目 LoRA：[VoidEclipseAI/ReFrameVideo-LoRA](https://huggingface.co/VoidEclipseAI/ReFrameVideo-LoRA)（ModelScope 镜像：[同名仓库](https://modelscope.cn/models/VoidEclipseAI/ReFrameVideo-LoRA)），推荐配方见上表（ReFrameVideo LoRA 1.0 + Pika H3 Flex 1.0，6 步）。

下载后重新启动 ComfyUI，再刷新 ReFrameVideo。主模型及 SAM 可以在对应面板选择；编码器、VAE、PE 等配套文件可以在图片生成 / 视频生成面板的「模型文件」里换（默认文件不在时自动用同一模型的其他量化版本）。LoRA 需要在生成面板手动选择，放进目录不会自动启用。

## 5. 安装节点

### 必需的自研节点

将本仓库的 `comfyui/ComfyUI-Reframe/` 整个目录复制到：

```text
ComfyUI/custom_nodes/ComfyUI-Reframe/
├─ __init__.py
├─ cleanup_route.py
├─ h3_inpaint_mask.py
├─ h3_mask.py
├─ io_nodes.py
└─ pyproject.toml
```

软件传给 ComfyUI 的素材放在 `ComfyUI/input/reframe/`，每个工作流跑完（成功、出错、停止）就通过节点包的 `POST /reframe/input/delete` 删掉；它只删 `input/reframe/` 里 `videops_` 开头的文件。节点包是旧版时文件会留在 `input/reframe/`，不影响生成，可以手动清。

重启 ComfyUI，确认存在节点 `ReframeH3InpaintMask`，以及 Reframe/IO 分类下的 6 个输入 / 输出标记节点（自己的改图 / 视频工作流用，见 `workflows/image/README.md`、`workflows/video/README.md`）。该包使用 ComfyUI V3 API，无额外第三方依赖。当前视频生成明确检查此节点，缺失会报错。

### ComfyUI 本身必须具备的节点

| 功能 | 关键节点 |
|---|---|
| SAM | `CheckpointLoaderSimple`、`SAM3_Detect`、`SAM3_VideoTrack` |
| H3 | `MiniMaxH3ReferenceToVideo`、`LTXVConcatAVLatent`、`LTXVSeparateAVLatent` |
| Qwen 改图 | `QwenImage21Cache`、`TextEncodeQwenImage21` |
| 描述/提示词增强 | `TextGenerate`、`PreviewAny`、`BatchImagesNode`（多图时） |
| H3 Image 改图 / H3 Image PE（ComfyUI 0.45.0+） | `MiniMaxH3ImageConditioning`、`ConditioningZeroOut`；PE 用 `TextGenerateV2` |
| 基础加载与输出 | `UNETLoader`、`CLIPLoader`、`VAELoader`、`LoadVideo`、`GetVideoComponents`、`CreateVideo`、`SaveVideo` |

这张表列关键能力，不是完整工作流节点清单。H3 的 `CLIPLoader` 还需支持 `type=minimax`，Qwen 的对应类型为 `qwen_image`。缺节点时先核对 ComfyUI 版本及启动日志，不要看到模型文件就认为环境已就绪。

### 可选：MatAnyone2 柔边抠像

安装作者的 `FuouM/ComfyUI-MatAnyone` 到 `custom_nodes/ComfyUI-MatAnyone/`，按其要求安装依赖。Windows 便携版在外层目录运行：

```powershell
.\python_embeded\python.exe -m pip install -r .\ComfyUI\custom_nodes\ComfyUI-MatAnyone\requirements.txt
```

然后放置 `checkpoint/matanyone2.pth` 并重启。当前后端调用的 API 节点名是 `MatAnyone2`，参数包括 `src_video`、`foreground_MASK`、`mask_frame` 等。不同作者的同类插件不能直接互换；以 `/object_info` 中注册的 API 名和字段为准。没装时边缘用 SAM 硬边。

## 6. 安装 ReFrameVideo 后端依赖

Windows 上双击 `start.bat` 就会自动做下面这几步：没有 `.venv` 就创建，`requirements.txt` 和上次装的不一样就重新安装（记录在 `.venv\requirements.installed.txt`）。装坏了删掉 `.venv` 文件夹再运行一次即可。

手动安装时，在仓库根目录 `ReFrameVideo/` 里用独立虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`websocket-client` 用于显示 ComfyUI 采样进度；缺失时只能显示阶段和用时。浏览器前端不需要 npm 构建，Node.js 只用于开发检查。

另需安装 FFmpeg 并将其 `bin` 目录加入 PATH；后端直接查找 `ffmpeg` 和 `ffprobe`，仅安装同名 Python 包不够：

```powershell
ffmpeg -version
ffprobe -version
.\.venv\Scripts\python.exe -c "import fastapi, uvicorn, numpy, cv2, PIL, requests, scipy, websocket; print('imports OK')"
```

**Linux / macOS**（代码按跨平台写，但目前只在 Windows 上实际跑过）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
sudo apt install ffmpeg python3-tk   # Debian / Ubuntu；macOS 用 brew install ffmpeg python-tk
```

- `python3-tk` 只用于「打开视频」时弹的选文件窗口；没装或在没有桌面的服务器上，直接在框里输入视频路径即可。
- `start.bat` 只能在 Windows 上用，其他系统运行 `.venv/bin/python start.py`。
- 「在文件夹里显示」：Windows / macOS 会选中文件，Linux 用 `xdg-open` 打开所在文件夹。

## 7. 启动与配置

先启动 ComfyUI，然后双击 `start.bat`（Linux / macOS：`.venv/bin/python start.py`）。第一次启动时窗口里会问 ComfyUI 地址：直接回车 = `http://127.0.0.1:8188`，输入 `mock` = 假引擎（只能看界面、不能识别和生成）。连不上时会提示，可以重新输入或仍然使用。地址记进 `app_settings.json` 的 `comfy_url`，以后不再问。要换地址：

```powershell
.\start.bat --comfy http://192.168.1.10:8188
```

浏览器打开 `http://127.0.0.1:8765/`。8765 上已经有 ReFrameVideo 在跑时直接复用（地址会记下，但正在跑的那个不会换，要换先关掉它）。

其它参数：`--port 8766`（换端口）、`--projects D:\my_projects`（换项目文件夹，父目录必须存在）、`--no-browser`。后端也认 `VE_PROJECTS`、`VE_COMFY`、`VE_PORT` 环境变量。直接起后端：`python app/server.py --port 8765 --comfy http://127.0.0.1:8188`（不带 `--comfy` = 假引擎，测试都靠这个）。

在设置中确认改图和描述等接入方式选择 ComfyUI。随后选择 SAM 模型、Qwen 版本、H3 主模型和所需 LoRA。Qwen 内置配方分别为 Turbo 8 步、完整版/int8 25 步；H3 推荐 ReFrameVideo LoRA 1.0 + Pika H3 Flex 1.0、6 步。设置 → 性能里的「导入视频的工作分辨率」默认长边 1920：更大的视频导入时先缩小再处理。

## 8. 安装后的逐步验收

1. 浏览器打开 ComfyUI；访问其 `/object_info`，确认关键节点及模型加载器列表存在。
2. 打开 ReFrameVideo 的 `/api/info`，确认是真实引擎而非 mock；设置中的连接检查通过只表示服务接口可用。
3. 导入一段短视频，确认能解码和播放，测试 SAM 识别与跟踪。
4. 移动物体，生成并选用一张首帧参考图，验证 Qwen 链路。
5. 检查粗剪、重绘范围、参考图和 LoRA，生成短片，验证 H3 链路。
6. 检查开头、中间、结尾以及音轨，再测试导出。完整操作见 [新手教程](../web/ui/tutorial-zh.md)。

工作流由后端代码构建并通过 ComfyUI API 提交，正常使用无需手动在 ComfyUI 画布中搭图。失败任务的 `comfy_graph.json` 是排查实际提交内容的依据。

## 9. 设置、项目与结果保存位置

仓库根目录 `app_settings.json` 保存模型选择、LoRA、采样参数、接入方式等；主题、语言和部分布局保存在浏览器本地。备份时不要仅复制页面文件。

默认项目位于仓库的 `projects/<pid>/`（`start.py --projects` 可以换）。旧结构的项目第一次打开时会自动迁移成下面这样：

```text
project.json                     项目数据（图层、版本、参考图、结果列表……）
原视频.mp4                       导入时的原视频（按工作分辨率缩过）
版本version/vN/视频video/        每个版本的视频与预览帧
结果result/vN/视频video/         视频结果：项目名_vN_K.mp4
结果result/vN/图片images/        图片候选和选用的那张（硬链接，不额外占空间）
中间文件work/生成gen/NNN/        每次生成的粗剪、mask、工作流、实际输入清单 inputused.txt
中间文件work/图片images/<id>/    图片编辑的底图、候选
背景图bg/  参考图refs/  masks/  缓存cache/（可以在设置里清）  导出export/
```

保留完整项目目录，避免单独移动或删除内部文件导致引用失效。ComfyUI 也会保存上传输入和输出，磁盘占用不只来自 ReFrameVideo。

`app_settings.json`、`api_keys.local.json`、`projects/` 都在 `.gitignore` 里，不会被提交。

### 安全说明

- 后端只监听 `127.0.0.1`，并且只接受本机页面的请求：`Host` 不是本机名的请求、别的网站发来的修改类请求一律拒绝（403）。不要用反向代理把它暴露到公网，它没有登录和权限管理。
- API key 以**明文**存在仓库根目录的 `api_keys.local.json`，后端从不把 key 发回浏览器（只告诉它有没有、尾号几位）。共用电脑时注意这个文件。

## 9.5 云端 API（图片生成 / 视频生成）

图片生成 / 视频生成面板顶上切到「API」，就调你配置的云端平台（只发输入图 / 粗剪、参考图和你写的提示词，效果不保证）。云端 API 只用于「图片生成」和「视频生成」面板；识别、抠图、看图写描述和 H3 视频一律走 ComfyUI。key 存在本机的 `api_keys.local.json`，不进 git。

软件不内置任何平台。在设置 → 云端 API →「接口配置」里「从模板新建」选一种格式，照平台的接口文档把空白字段填完，点「保存为平台」，再填 key、点「保存连接设置」：

| format | 怎么发 | 例子 |
|---|---|---|
| `openai_edits` | `POST {base_url}/images/edits`，multipart 上传图片，同步返回 `data[0].b64_json / url` | OpenAI 图片编辑接口 |
| `json_sync` | `POST {base_url}{path}`，图片放 JSON 字段里（base64 data URI），直接返回图 | 火山方舟 Seedream |
| `async_task` | 提交后拿任务号，`GET {base_url}{poll}` 轮询，完成后下载图片链接；只有这种能做视频生成 | APIMart |

配置字段（`json_sync` / `async_task`）：

| 字段 | 意思 |
|---|---|
| `base_url` | 平台地址，例如 `https://api.example.com/v1` |
| `image_model` | 默认的图片模型（必填；面板里可以改） |
| `path` | 提交地址，例如 `/images/generations` |
| `image_field` | 图片放在哪个字段（`image`、`image_urls`…）；第 1 张是要改的图，后面是参考图 |
| `single_as_string` | 只有一张图时给字符串（否则总是数组） |
| `size` | `wxh_ark`（宽x高，按火山方舟各模型的像素范围缩放）/ `wxh`（原图宽x高）/ `ratio`（最接近的比例，如 `16:9`）/ `none`（不发） |
| `extra` | 额外固定发的字段，例如 `{"watermark": false}`、`{"resolution": "2K"}` |
| `max_images` | 最多几张图（原图 + 参考图），多的参考图不发；0 = 不限 |
| `result` | 结果在返回值里的位置，点分路径，数字是第几个。指到的可以是含 `b64_json` / `url` 的对象，也可以直接是网址 |
| `task_id` | （异步）任务号的位置，例如 `data.0.task_id` |
| `poll` | （异步）查询地址，`{id}` 换成任务号，例如 `/tasks/{id}` |
| `status` / `done` / `failed` | （异步）状态的位置，以及表示完成、失败的状态值 |
| `error` | （异步）失败原因的位置 |
| `models_query` | 列模型（`GET {base_url}/models`）时带的参数，例如 `{"category": "image"}` |

### 视频生成走 API

「视频生成」面板顶上也可以切到「API」（切换时会弹提示：个人测试下 Seedance 暂时无法完成视频补全）。只发三样东西：粗剪（空的地方涂灰 128，提示词里的 `@视频1`）、面板里勾选的参考图（`@图片1`、`@图片2`…）、你写的提示词（原样发）。不调 4090：不跑 H3，也不问 Qwen-VL。平台出的视频就是成片，帧数按原片对齐、带原片声音。

只有配置里有 `video_path` 的 `async_task` 平台支持（作者测过 APIMart · `seedance-2-5-flash`）。视频字段：

| 字段 | 意思 |
|---|---|
| `video_model` | 默认视频模型（面板里可以改） |
| `video_path` | 视频提交地址，例如 `/videos/generations` |
| `video_field` / `video_image_field` | 粗剪视频 / 参考图的网址放哪个字段（`video_urls` / `image_urls`） |
| `upload_video` / `upload_image` | 素材先上传换网址的地址；`upload_url` = 上传返回里网址的位置 |
| `video_result` | 结果视频网址的位置，例如 `data.result.videos.0.url.0` |
| `video_extra` | 额外固定发的字段，例如 `{"omni_reference_task_type": "edit", "size": "adaptive"}` |
| `video_resolutions` | 可选分辨率（发在 `resolution` 字段） |
| `video_max_images` | 最多几张参考图 |
| `video_limits` | 平台对输入视频的限制，发之前在本机检查：`min_s` / `max_s` 时长、`min_ratio` / `max_ratio` 宽高比（不合格直接报错，不上传）；`min_pixels` / `min_side`（不够就等比放大）、`min_fps`（不够就补帧，时长不变）、`max_mb` 上传大小 |

注意：
- 作者测试时，Seedance 还不能稳定地补全灰色空区：可能把灰色留着，或在空缺处画出多余的人，请仔细检查结果。
- 电影片段可能被 Seedance 拒收；含真人脸的素材平台可能要求先过人脸素材审核。
- 调用费用由平台按其价格收取。

不属于这三种格式的平台，可以在 ComfyUI 里用它的节点搭工作流，放进 `workflows/image/`（见里面的 README），在 ComfyUI 模式下选用。

## 10. 常见问题

| 现象 | 优先检查 |
|---|---|
| 页面能开，但是假引擎 | `app_settings.json` 的 `comfy_url` 是否设了（`start.py --comfy`）；是否复用了旧服务 |
| 模型下拉为空 | 后端能否访问 ComfyUI；文件是否放在对应机器的正确模型目录 |
| 文件存在但加载失败 | 文件名、量化格式、配套编码器/VAE、ComfyUI 支持情况及下载是否完整 |
| 找不到 ReframeH3InpaintMask | 自研节点文件夹层级是否正确；是否重启；启动日志有无导入异常 |
| Qwen 主模型存在仍失败 | 两个配套文件和 Qwen 2.1 专属节点是否齐全 |
| 提示词增强失败 | PE 编码器是否在 ComfyUI 上；选的是 H3 Image PE 时 ComfyUI 是否 0.45.0 以上，以及任务提示词是否下载成功（见下面「H3 Image PE 的提示词」） |
| MiniMax H3 Image 灰着选不了 | ComfyUI 版本（要 0.45.0+）、`minimax_h3_image_pruned_int8_convrot.safetensors` 和 `minimax_h3_image_vae_fp16.safetensors` 是否放好 |
| MatAnyone2 失败 | 插件 API 名和字段、插件自己的 checkpoint 目录及其 Python 依赖 |
| FFmpeg 找不到 | 在启动后端的同一终端运行 `ffmpeg -version`，更新 PATH 后重开终端 |
| 显存不足 | 缩短测试视频、降低工作分辨率，查看 ComfyUI 日志；不要直接承诺低显存可用 |
| 参考图没生效 | 是否已选用并勾选、是否因布局过期或尺寸不符被跳过 |
| 后端版本过旧 | 前后端来自同一个仓库版本；重启后端 |
